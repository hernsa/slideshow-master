Why HTML Beats PPTX for Tech Talks

Speaker Ada Demo · Frontend Engineer · DevConf Main Stage

Live code, live demos, zero "works on my machine" font drama.

Welcome the room, introduce Ada, set the promise: real code on real slides, everything the audience sees ships as a link after the talk.

The one sentence to remember

Slides are software — so version them, test them, and ship them like software.

Everything else in this talk is a consequence of that sentence.

Land the thesis slowly. Repeat it twice. Every later slide maps back to version, test, or ship.

The problem with PPTX

Death by deck

01

Binary blobs

No diff, no blame, no pull request. Two Edits_final_FINAL.pptx and nobody knows what changed.

02

Font roulette

Calibria on your laptop, tofu boxes on stage.

03

Dead demos

Screenshots of code you cannot run, copy, or click.

Click through fragments one at a time. Ask for a show of hands on FINAL_final files. Pause for laughs before moving on.

Steal this workflow

One rule that saves every demo

Tip: freeze a fallback build the night before. Tag it v1.0-fallback so venue wifi can die and you still present.
  • Commit slides and demos to the same repo
  • Record a 60-second offline screen capture as backup
  • Print speaker notes — paper never needs wifi
Tell the Berlin story: venue wifi died, fallback tag saved the keynote. The callout is the slide people photograph.
